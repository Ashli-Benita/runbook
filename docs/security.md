# Security Architecture & Rules

## Core Security Principles

### 1. No Arbitrary Command Execution
- The agent NEVER accepts free-form shell command strings from LLM output, user input, or runbook files.
- Command execution is locked to a predefined, typed `ActionType` Enum registry.

### 2. Risk Classification Matrix
| Action Type | Description | Risk Level | Requires Approval |
| :--- | :--- | :--- | :--- |
| `CHECK_DATE` | Query system date/time | `SAFE` | No |
| `CHECK_UPTIME` | Query system uptime | `SAFE` | No |
| `CHECK_DISK_USAGE` | Query disk usage | `SAFE` | No |
| `CHECK_MEMORY` | Query memory usage | `SAFE` | No |
| `CHECK_APPLICATION_STATUS` | Query application status | `SAFE` | No |
| `VERIFY_APPLICATION` | Verify service response | `SAFE` | No |
| `GENERATE_REPORT` | Compile execution summary | `SAFE` | No |
| `RESTART_APPLICATION` | Restart application service | `HIGH` | **YES** |
| `STOP_APPLICATION` | Stop application service | `HIGH` | **YES** |
| `START_APPLICATION` | Start application service | `HIGH` | **YES** |

### 3. MCP Authorization Check
- Before running any high-risk action, `McpToolExecutor` queries the database for a matching `APPROVED` status on `ApprovalRequestEntity`.
- Unapproved or rejected actions immediately return `APPROVAL_REQUIRED` or `EXECUTION_DENIED`.

### 4. Input Validation
- All uploaded Markdown files are sanitized and parsed into structured Java objects.
- Unknown actions generated by LLM planner are rejected during plan validation.
